# Структура проекта DormSupport

Этот документ описывает, как организован репозиторий DormSupport и где находятся основные части системы.

## Структура корневого репозитория

```text
dorm-support-infrastructure/
├── auth-service/             # сервис аутентификации и управления пользователями
├── gateway-service/          # внешний Gateway и маршрутизация запросов
├── issues-service/           # API и бизнес-логика заявок
├── notifications-service/    # сервис уведомлений и обработка событий
├── frontend/                 # веб-интерфейс
├── documents/                # документация проекта (отдельный Git submodule)
│   └── dormsupport/
│       ├── diagrams/          # диаграммы архитектуры и сценариев
│       ├── mvp.md             # объём текущего MVP
│       ├── requirements.md    # требования к системе
│       ├── data-model.md      # модель данных
│       ├── notifications.md   # описание уведомлений
│       ├── roadmap.md         # план развития
│       └── project-structure.md # описание структуры проекта
├── docker-compose.yml         # состав и связи локального окружения
├── Makefile                   # команды для работы с окружением
└── README.md                  # обзор проекта и быстрый запуск
```

Каталоги сервисов, `frontend` и `documents` подключены к корневому репозиторию как Git submodules. Они имеют собственные репозитории и версии. Корневой репозиторий хранит ссылки на конкретные версии этих компонентов и файлы для их совместного запуска.

## Backend-сервисы

Backend-сервисы написаны на Java и собираются Maven. Их исходники и конфигурация находятся в `src/main/`.

```text
<service>/
├── src/main/java/com/dormsupport/<service>/
│   ├── api/                    # HTTP-контроллеры и модели запросов/ответов
│   ├── config/                 # конфигурация приложения (если требуется)
│   ├── service/                # прикладная логика (если требуется)
│   └── ...                     # пакеты, разделённые по областям ответственности
├── src/main/resources/
│   ├── application.yml         # настройки приложения
│   ├── db/init.sql             # начальная схема базы данных (если есть)
│   ├── static/openapi.yaml     # HTTP API-контракт
│   └── events.schema.json      # контракт Kafka-событий (если используется)
├── pom.xml                     # Maven-конфигурация и зависимости
├── Dockerfile                  # сборка контейнера сервиса
└── README.md                   # назначение сервиса и особенности
```

Состав пакетов отличается между сервисами в зависимости от их задач. Например, в `issues-service` код разделён на пакеты `issue`, `category`, `history`, `security` и `client`; в `auth-service` — на `api`, `service`, `user` и `config`. Это доменные части конкретного сервиса, а не общий код, разделяемый между всеми сервисами.

### Назначение сервисов

- **`gateway-service`** принимает внешние запросы и направляет их к интерфейсу или backend-сервисам. Это единственная точка входа, опубликованная для локального окружения.
- **`auth-service`** отвечает за учётные записи, вход, роли и выдачу JWT-токенов.
- **`issues-service`** отвечает за категории заявок, сами заявки, их статусы и историю изменений. Для проверки пользователя он также содержит клиент Auth service.
- **`notifications-service`** предназначен для обработки событий и уведомлений. Его контракт событий хранится рядом с исходниками.

У каждого backend-сервиса свой `pom.xml`, `Dockerfile`, README и набор ресурсов. Поэтому код, API-контракт, настройки и сборка сервиса обычно меняются внутри каталога этого сервиса.

## Frontend

```text
frontend/
├── src/
│   ├── main.tsx                # точка входа React-приложения
│   ├── api.ts                  # взаимодействие с API
│   └── styles.css              # стили интерфейса
├── index.html                 # HTML-шаблон приложения
├── vite.config.ts              # конфигурация Vite
├── tsconfig.json               # настройки TypeScript
├── package.json                # зависимости и команды npm
├── Dockerfile                  # сборка frontend-контейнера
└── README.md                   # описание frontend и его запуска
```

Frontend использует React, TypeScript и Vite. В контейнерной конфигурации он доступен через Gateway, а не как отдельный опубликованный наружу сервис.

## Инфраструктура и интеграции

Файл `docker-compose.yml` описывает компоненты локального окружения и их связи:

- frontend и четыре backend-сервиса;
- три экземпляра PostgreSQL: `identity_db`, `issues_db`, `notifications_db`;
- Kafka;
- зависимости запуска и health checks контейнеров.

Файл `Makefile` содержит команды для обновления репозиториев компонентов, сборки и управления окружением. В частности, цель `up` подтягивает изменения ветки `dev`, синхронизирует submodules и запускает Compose.

У каждого сервиса собственная база данных. Kafka используется для взаимодействия через события. Их HTTP- и событийные контракты располагаются рядом с кодом сервисов, которые эти контракты предоставляют или используют.

## Документация

Проектная документация находится в `documents/dormsupport/`:

- `mvp.md` — актуальный объём MVP;
- `requirements.md` — функциональные требования и правила;
- `data-model.md` — сущности и поля предметной области;
- `notifications.md` — описание целевой системы уведомлений;
- `roadmap.md` — план дальнейшего развития;
- `diagrams/` — диаграммы в форматах SVG/PNG и исходниках Mermaid;
- `openapi.yaml`, `openapi.json`, `events.schema.json` — общие проектные контракты и материалы целевой архитектуры.

Уточняйте актуальность общих документов по MVP и контрактам внутри сервисов: часть материалов описывает целевую расширенную архитектуру, а не уже реализованное поведение.

## Где искать изменения

| Тип изменения | Основное расположение |
|---|---|
| Экран или поведение интерфейса | `frontend/src/` |
| Вход, пользователи, роли и токены | `auth-service/src/main/` |
| Внешняя маршрутизация | `gateway-service/src/main/` |
| Заявки, категории и статусы | `issues-service/src/main/` |
| Уведомления и потребление событий | `notifications-service/src/main/` |
| HTTP API-контракт | `src/main/resources/static/openapi.yaml` соответствующего сервиса |
| Схема Kafka-событий | `src/main/resources/events.schema.json` соответствующего сервиса |
| Схемы и начальные данные баз | `src/main/resources/db/` соответствующего сервиса |
| Состав и связи локальных контейнеров | `docker-compose.yml` |
| Команды управления окружением | `Makefile` |
| Требования, модель и диаграммы | `documents/dormsupport/` |
